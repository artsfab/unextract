# GUI仕様

役割: GUI (`unextract-gui.exe`) が利用者に保証する機能・状態・情報・安全性の制約と利用品質の正本。GUIを変更するときだけ読む。CLIの引数・機械可読出力・判定・削除の安全性は [CLI](cli.md)・[機械可読出力](machine-output.md)・[ファイル安全性](filesystem.md) などが定め、本書は再定義しない。採用した画面構成と実装の配置は [ARCHITECTURE](../ARCHITECTURE.md#gui)、選定理由は [RATIONALE](../RATIONALE.md#gui)、検証は [TESTING](../TESTING.md#gui) と [M14](../MANUAL_TESTS.md#m14) にある。

[位置づけ](#scope) / [検索](#search) / [Target](#targets) / [状態](#target-states) / [選択](#selection) / [モード](#modes) / [解析](#analysis) / [削除確認](#delete-confirmation) / [削除実行](#delete-run) / [終了](#exit) / [削除後](#delete-results) / [ログ](#log) / [CLI連携](#cli-integration) / [セッション](#session) / [配布](#deployment) / [利用品質](#quality) / [限界](#limitations)

本書は画面構造・レイアウト・操作表現を定めない。「表示する」「確認できる」は、利用者がその情報を画面上で得られることを指し、置き場所や見せ方を指定しない。表示文言の例も形式の指定ではない。本書の「CLI」は同梱の `unextract.exe` を指す。

<a id="scope"></a>
## 位置づけと境界

大量のZIPを保管しているディレクトリ配下について、過去に展開したファイルをCLIの既存の安全判定で確認・削除し、ディスク容量の整理を行いやすくするGUIラッパである。

- GUIはファイルの一致判定・削除の安全性を判断しない。target の実名解決・NTFS・拒否位置・reparse/hardlink/ADS・同一性・TOCTOU・一致判定を実装せず、CLIに任せる。
- GUIは CLI を子プロセスとして起動し、プロセス境界越しに機械可読出力 (`--jsonl`) と終了コードを使う。Core / Windows / Cli のDLLを参照しない。
- 1つのArchiveに複数のTargetを設定できる (例: `A.zip → D:\Reference`、`A.zip → D:\Reference\A`)。内部ではすべて独立した `archive + 解決後のtarget + mode` のジョブとして扱い、「1 Archive : N Target」は表示上のまとまりである。CLIの処理単位は変えない。

対象外 (初版): RAR / 7z、任意列による高度なソート、セッションの保存・復元、複数の検索ディレクトリ履歴、お気に入り、並列解析・並列削除、常時ログファイル (削除の[実行ログ](#log)を除く)、実行ログからのジョブ再開・結果の再読込・ログの保持期間管理、環境変数の展開、GUIによる削除安全性ロジックの再実装、インストーラー・自動更新。

<a id="search"></a>
## Archive検索

- 検索対象のディレクトリは利用者が明示する。前回のディレクトリは[保存した1件](#session)を初期値にできる。
- 対象はZIPだけで、拡張子 `.zip` の大小文字を区別しない。ZIPの中身は検索で読まない。
- 「サブディレクトリも検索」を提供し、初期値はON。再帰検索で reparse point のディレクトリへ進入しない ([限界](#limitations))。hidden / system を理由に黙って一括除外しない。
- アクセス拒否などで列挙できない場所、走査中に消えた・属性を取得できなかった項目は、その場所だけ飛ばして検索を続け、利用者に通知する。この通知は検索の診断であり、CLIによる解析の成否とは区別する。
- 結果はパスの昇順 (序数比較)。各Archiveについて、少なくともファイル名・フルパス・ファイルサイズ・更新日時・Target数を表示する。
- ファイル名またはパスの文字列で表示を絞り込める。絞り込みは選択状態を変えない。

<a id="targets"></a>
## Targetの追加・テンプレート・重複・一括設定

各ArchiveにTargetを追加できる。プリセットは「Archiveと同じディレクトリ」 (`{{archive.dir}}`) と「Archive名のディレクトリ」 (`{{archive.dir}}\{{archive.name}}`) で、カスタムとして任意の固定Windowsパスまたは変数を含むテンプレート (例: `D:\Extracted`、`{{archive.dir}}\extracted`、`D:\Work\{{archive.name}}`) を入力できる。

テンプレートはGUIだけの概念で、CLIには必ず解決後の実パスを渡す。Targetは解決後の実パスで識別でき、登録に使ったテンプレートも確認できる。

- 変数は `{{archive.dir}}` と `{{archive.name}}` の2つだけで、綴りの完全一致 (大小文字を区別) で認識する。`{{archive.dir}}` はArchiveのフルパスのディレクトリ部分、`{{archive.name}}` はファイル名から最後の拡張子だけを除いたもの (`A.zip` → `A`、`a.b.ZIP` → `a.b`)。
- 環境変数・シェル変数・`~` などは展開しない。
- 次は登録エラーとし、Targetを追加しない: 未知の変数・閉じていない `{{` などの不正な構文、`{{archive.name}}` が空になる場合、解決結果がドライブ文字で始まる有効な絶対パスにならない場合 (相対パス、Windowsで無効な名前、`.`・`..` の成分を含むものなど)。正規化で dot 成分を隠して受理しない。
- 登録時の検査は解決結果の形式だけを見る。Targetとして受け付けられるかはCLIの入力検証が判定する ([存在確認](#target-states))。

重複: 同一Archiveに、解決後の実パスが同じTargetを複数登録しない。判定は展開後のパス文字列を正規化 (区切りを揃え、ドライブルートの意味を保って末尾の区切りを除き、大小文字を無視) したもので行い、junction などをたどった最終パスやFile IDによる同一性は調べない。最終パスが同じジョブが2つあっても、2つ目の `delete` は再検証によって `MISSING` などになるだけである。同一Archiveへの親子関係のTargetと、異なるArchiveが同じTargetを使うことは許す。

一括設定: 検索結果の全Archiveに同じTargetルールを追加できる。表示の絞り込みや選択状態に依存せず、既存のTargetを消さない追加方式とする。解決後のパスが既存のTargetと重複するArchiveではその追加だけを飛ばし、解決エラーはArchiveごとに通知する。

<a id="target-states"></a>
## Targetの状態と存在確認

「除去」はGUI上のTarget設定を消すことであり、ファイルの削除 (`delete`) ではない。

| 状態 | 編集 | 除去 | 解析 | `delete` |
|---|---|---|---|---|
| 未解析 (解析失敗・キャンセルを含む) | 可 | 可 | 可 | 不可 |
| 解析済み | 不可 | 可 | 再解析可 | 可 ([削除確認](#delete-confirmation)の条件による) |
| `delete` 実行済み (CLIのプロセスが一度でも起動したもの。結果を問わない) | 不可 | 可 | 再解析可 | 再解析が正常完了するまで不可 |

解析済みTargetのパスを変更する編集は設けない。別のTargetにしたい場合は除去して追加する。`delete` 実行済みによる編集ロックは、再解析の失敗やモード変更でも解けない。

存在確認: 存在しないTargetも登録できる。存在しないことを確認したTargetは「存在しない」と表示して解析不可とし、後から作られた場合は解析開始時に再評価する。アクセス拒否などの確認不能を一律に「存在しない」と断定せず、正式な判定はCLIに委ねる。GUIの存在確認は表示のためだけで、CLIの入力エラーのコード (`TARGET_NOT_FOUND` など) は解析失敗の詳細として表示するだけで状態の分岐に使わない ([CLI連携](#cli-integration))。

<a id="selection"></a>
## 選択

- Targetの選択は「一括操作の対象」を表す。新規のTargetは選択した状態で追加する。
- 選択は表示の操作 (絞り込み、閲覧する項目の切り替え、表示範囲の開閉など) から独立し、表示から隠れても変わらない。
- 「すべて選択」「すべて解除」「表示中をすべて選択」「表示中をすべて解除」を提供する。
- Archive単位で、配下のTargetの選択をまとめて切り替えられる。Archive単位の状態は「全Target選択」「一部選択」「全Target未選択」を区別して示す。まとめて選択すると全Targetを選択、解除すると全Targetを解除し、過去の子の選択状態は保持しない。Targetが0件のArchiveではまとめての操作はできない。

<a id="modes"></a>
## Strict / Fast

- 検証モードはセッション全体で共通。初期値はStrict。意味は[モード契約](../SPEC.md#modes)による。
- Fastを選んでいる間は、内容の一致を確認しないモードであること、特に同一パス・同一サイズの変更ファイルも削除され得ること、ZIPから正常に展開できることを確認しないことを明示する。
- 解析済みのTargetがある状態でモードを変える場合は、確認のうえ全解析結果を破棄する。取り消せば元のモードと結果が残る。別のモードの候補を再利用しない。

<a id="analysis"></a>
## 解析・進捗・結果

解析はCLIの `analyze` として実行し、GUIでは「解析」と表示する。

- Target単位の解析に加え、「Archive配下の未解析Target」と「選択中の未解析Target」の一括解析を提供する。キューは開始時に固定し、表示の絞り込みを条件にしない。並列化せず1 Targetずつ順に実行する (同一Archive配下はTarget登録順)。1つが失敗しても残りを続ける。
- 成否は[実行結果の判定](#cli-integration)による。正常完了のときだけ全entryを解析結果として採用する。それ以外は「解析失敗」とし、途中まで受け取った `entry` は候補にも結果にも使わず、そのTargetを未解析に戻して、CLIから得たエラー情報を詳細として示す。再解析を開始した時点で従来の結果を削除の根拠から外し、失敗・キャンセルしても復活させない。
- 進捗: 全体 (Target数)、現在のArchiveとTarget、そのTargetのエントリ単位の進捗 (例: `7 / 20 Targets`、`Checking 421 / 842`) を表示する。エントリ単位は `run.selected` と受信した `entry` の件数から求める。CLIは進捗専用の出力を持たないため、`run` の前は準備中と示し、Strictで巨大なファイルを比較している間は件数が進まないことを説明する。推測のバイト進捗は出さない。削除中も同じ方法で全体と現在のTargetを示す。
- 実行中 (解析・削除のバッチを確定してから完了まで) は、モード変更・再検索・Targetの追加/編集/除去・選択の変更などの設定操作をセッション全体でロックする。閲覧・絞り込み・表示の切り替えと解析のキャンセルは使える。
- キャンセルすると現在の解析を中止し、そのTargetの途中結果は採用せず未解析に戻し、残りのキューへ進まない。
- 結果: 複数のTargetを見渡すときに各Targetの要約 (分類ごとの件数。例: `Matched 842 / Modified 3 / Missing 12 / Skipped 1`) が分かる。各Targetについて正常完了した解析の全エントリを確認でき、分類による絞り込みとパス文字列による検索を提供する。分類名はCLIの `MATCHED`・`SAME_SIZE`・`MODIFIED`・`MISSING`・`SKIPPED_SPECIAL_FILE`・`DIRECTORY` との対応を保ち、Fastの削除候補は `Same Size` として示す。そのモードで発生しない分類は表示しなくてよい。
- サイズ: 削除候補ファイルの論理サイズ合計を「削除候補サイズ」などの名称で表示し、「必ず解放される物理ディスク容量」とは扱わない (NTFS圧縮・sparse file などで一致しない)。値はCLIが報告した候補の `entry.length` ([レコード](machine-output.md#records)) の合計で、GUIはファイルシステムを独自に計測しない。合計は64bitを超えても桁あふれさせない。重複Targetなどによるジョブ間の重複計上を実容量の保証にしない。

<a id="delete-confirmation"></a>
## 削除できる条件と確認

削除対象にできるのは、選択中のTargetのうち、現在のモードで正常に解析完了し、`delete` 実行後に再解析していないものでなく、存在しないことを確認したものでなく、削除候補が1件以上あるものだけである。選択中に削除できないTarget (未解析、解析失敗、存在しない、`delete` 実行済み、候補0件) があれば対象から除外し、確認で除外したTargetと理由を示す。候補0件のTargetでは `delete` を実行しない。

処理対象は、直前に正常完了した解析で削除候補となったファイルエントリ (Strictは `MATCHED`、Fastは `SAME_SIZE`) の生のFullNameに限る。エントリ単位で選ぶ機能はない。解析結果は処理範囲を限定するためだけに使い、個々のファイルの削除可否は `delete` が実行時点の状態を再検証して決める。解析後に条件を満たさなくなったファイルは削除されず、解析時に候補でなかったファイルは後から一致してもその実行の対象に加えない。

確認は一括実行の前に1回だけ行い、少なくとも次を示す。

- Target数
- 削除候補ファイル数 (解析時点の最大件数であり、再検証で削除されないファイルがあり得ること)
- 削除候補の論理サイズ
- 完全削除であること (ごみ箱を使わない)
- 途中で停止しても、それまでに削除したファイルは元に戻らないこと
- 実際に削除するTargetの一覧 (Archiveと実パス。省略せず全件)
- 表示の絞り込みで隠れている選択済みTargetが含まれる場合はその旨と該当Target (対象から外さない)
- Fastでは、内容の一致とZIPから正常に展開できることを確認しないこと、同一パス・同一サイズの変更ファイルも削除され得ること

確認の既定の操作は取消とし、利用者が明示的に承認するまでCLIを起動しない。承認時点のTarget・モード・解析結果・候補を固定し、その後の選択・絞り込み・遅れて届いた操作で変えない。承認時に計画が現状 (モード・解析結果・Target) と一致しなければ開始しない。このGUIの確認を一括削除の利用者確認とし、各 `delete` はCLIの個別確認を `--yes` で省略する。省略するのは確認だけで、検証・再検証は省略しない。

<a id="delete-run"></a>
## 削除の実行とキュー

削除も1 Targetずつ順に実行する。GUIの解析結果を削除の許可証にせず、CLIが通常の実行として必要な検査・再検証を行う。各Targetの `delete` は常に次の形で起動し、archive・target・entries・ログはすべて絶対パスで渡す。

```text
unextract delete <archive> --target <dir> [--fast] --entries <file> --yes --jsonl --log <file>
```

entriesファイル: 各Targetの起動直前に、OSの一時ディレクトリ直下へ一意な名前で新規作成し、候補の生のFullNameをUTF-8 (BOMなし)・LF区切りで1行ずつ書く (大小文字・区切り・空白を補正しない)。書き込みとcloseを終えてからCLIを起動する。CLIプロセスの終了を確認した後 (確実な起動失敗・準備失敗ではその判断後) に、GUIは自分が作成したそのファイルだけを削除する。終了を確認できない間は削除しない。削除に失敗してもCLIの結果の判定は変えず、パス付きで通知する。GUIが異常終了した後の残骸は、次回起動時にも探索・自動削除しない。他のファイルを削除する機能はGUIに設けない。

entriesの上限: 正常解析の候補であっても、entriesファイルがCLIの[ファイル全体の上限](cli.md#entries)を超える場合がある (ZIP側の上限はUTF-16の名前で計上するため、長い非ASCII名が多いとUTF-8では超え得る)。GUIは準備時にentriesのUTF-8の実バイト量 (各行末のLFを含む) を上限と比べ、上限ちょうどは許可する。超過時はそのTargetのCLIを起動せず、削除対象の一覧がCLIの上限を超えるため削除処理を開始できない旨を示し、下記の準備失敗として扱う (解析結果を保持し、`delete` 実行済みにせず、後続を開始しない)。再解析では解消しない制限であり、自動分割・自動再試行・CLI上限の変更は行わない。CLI自身の検査も維持される。

キュー:

- CLIのプロセスが起動した時点で、そのTargetを `delete` 実行済みにする。その後の結果 (正常終了、エラー終了、出力の非互換・異常、結果不明) は問わない。起動が成功したか判断できない場合は起動したものとして扱う。
- エラー終了 (`DELETE_FAILED` だけの場合、入力エラー、出力の非互換・異常を含む) したら、後続のTargetの `delete` を開始しない。
- 起動失敗: OSがプロセスの作成を失敗として返し、CLIが開始されていないと確実に判断できる場合は「CLIを起動できず、削除処理は開始されていない」ことを示す。そのTargetは解析済みのまま残し、再解析なしで再び `delete` できる。後続は開始しない。CLIの起動前のGUI側の準備 (entriesの作成、ログの保存場所の用意、上記の上限確認など) の失敗も同じに扱う。
- 正常終了したTargetはそのまま。開始しなかった後続のTargetは解析済みのまま残し、「未実行」と表示する。
- 自動再解析・自動再試行はしない。

<a id="exit"></a>
## 実行中のアプリ終了とGUIの異常終了

- `delete` の実行中に終了を要求されても、実行中のCLIを強制終了しない。現在のTargetの `delete` が終了するまで待ち、結果を受け取り、entriesを後始末してから、残りのキューに進まずに終了する。待つ間は現在のTargetが終わり次第終了する旨を示し、新しいジョブを開始しない。繰り返し終了を要求しても強制終了しない。無応答の時間を理由に強制終了しない。
- `analyze` の実行中の終了要求では、解析をキャンセルしてから終了してよい (`analyze` は削除しない)。
- GUIがクラッシュした場合に実行中のCLIを道連れに終了させる仕組み (終了時に子を強制終了する Job Object など) は設けない。GUIが消えた後にCLIが最後まで処理することは保証しない (出力の失敗を検出すればCLIは止まる)。CLIが処理を続ける場合も、渡した処理範囲を各エントリの再検証つきで処理するだけで、承認した範囲を超えない。
- 再起動後に中断したジョブやセッションを復元しない。結果は[実行ログ](#log)で確認する。

<a id="delete-results"></a>
## 削除後の表示

正常終了 ([判定](#cli-integration)) のTargetは「削除完了」とし、削除成功件数と削除したファイルの論理サイズ合計 (`DELETED` の `entry.length` の合計) を示す。受信できた範囲だけの値を総削除サイズとして補完しない。

解析結果は画面に残してよいが、再解析までは `delete` に使えず、その候補はセッション全体の削除候補の合計に含めない。

各Targetの直前の `delete` 結果 (表示内容と実行ログのパス) は、解析状態とは別に1件だけ保持する。対象はCLIのプロセスが起動した (起動成否不明を含む) `delete` の結果だけで、再解析 (成功・失敗) やモード変更では消さず、そのTargetで次に起動した `delete` の結果で置き換える。一括削除でそのTargetのCLIを起動しなかった場合 (前のTargetの停止による未実行、準備失敗、確実な起動失敗) は、直近の一括削除の状態として別に表示し、直前の `delete` 結果とログのパスは保持する。この状態はそのTargetが次の一括削除に加わったときに置き換える。履歴、永続保存、複数回分の保持はしない。

エラー終了では、可能な範囲で削除済み件数・`DELETE_FAILED` 件数・未処理件数・停止理由・「削除された可能性あり」の対象を示す。読み方の正本は機械可読出力の [result](machine-output.md#result) と[完了境界](machine-output.md#boundary)で、GUIは受信内容に応じて次のとおり示す。

- 出力を正しく受信でき `run` が無い: 削除0件。`result` があればその `error` を示す。
- `run` と `result` を受信した: `result` の件数・停止理由と、`entry` および `result.error` の `possibly_deleted` を示す。実終了コードが `result` と違えば終了コードを優先し、`result` は詳細として残す。`internal_error` で `deletion_started` が true なら、次の項の規則も適用する。
- `run` があり `result` が無い (クラッシュ、強制終了、出力の途絶): 承認した候補を解析時の `index` の順 (ZIPの順) に並べ、最後に受信した `entry` の次の1件を「不明 (削除された可能性あり)」、それ以降を未処理とする。entriesの行順や `index` の数値+1は使わず、次の候補が無ければ架空の不明対象を作らない。
  - この特定は `delete` 時のZIPの順が解析時と同じことを前提とする。受信内容から解析後のZIPの変化が分かる場合 (`run.entries_total` が解析時のエントリ数と違う、または受信した `entry` の `index` が同名の候補の解析時の `index` と違う) は1件を断定せず、`entry` を受信していない候補をすべて「結果不明 (削除された可能性あり)」とする。
  - `result.error` の `possibly_deleted` と `entry_name` でCLIが対象を報告していれば、変化の検出の有無にかかわらず、解析時の順による推定よりその報告を優先する。
  - 受信内容に表れないZIPの変化はGUIでは検出できない ([限界](#limitations))。解析時の順で特定した1件や未処理の件数には推定である旨を添え、確認先として実行ログを示す。
- 出力の非互換・異常、または承認した範囲と一致しない出力 (`run.selected` が承認した候補数と違う、承認していない名前の `entry` や `entry_name`) を受信した場合: 部分的な内容から件数を確定せず「結果不明」とし、原因と実行ログのパスを確認先として示す。`run` を受信していなければ、そのログパスはCLIが作成したと確認できない予定のパスとして示す。

`delete` の `run.target` が解析時の `run.target` と違う場合は、詳細にその旨を表示するだけで、判定には使わない。

<a id="log"></a>
## 実行ログ

`delete` ごとにCLIの `--log` で実行ログを残す。中身はCLIの機械可読出力そのもので ([実行ログ](machine-output.md#log))、GUIは書き込まず、加工しない。目的はGUIやCLIに問題が起きても後から「何を削除したか」を確認できることで、監査、ジョブの再開、セッションの復元には使わない。

- 保存場所は `%LOCALAPPDATA%\unextract\logs\`。用意できなければ、その `delete` を開始せずに停止する ([準備失敗](#delete-run))。GUIはログファイルを先に作らず、新規作成はCLIに任せる。
- ファイル名は `delete-<一括削除の開始時刻 (UTC、yyyyMMdd-HHmmss)>-<その一括削除でのTargetの通し番号 (3桁以上のゼロ埋め)>.jsonl`。起動前に同名のファイルがあれば未使用の別名 (GUID付き) を使う。
- 起動前の確認の後に他のプロセスが同名のファイルを作った場合、CLIは上書きせず入力エラーにする。GUIはこれを通常のエラー終了として扱い、自動再試行しない。
- GUIの多重起動は禁止しない。インスタンス間の調整はログ名の重複回避以外に行わない。
- 削除結果の詳細でログのパスを確認でき、ログの保存フォルダーを開く操作を提供する。フォルダーがまだ無いときはその旨と予定のパスを示す。
- ログを自動削除しない。保持期間の管理、ログの一覧・検索・再読込は提供しない。

<a id="cli-integration"></a>
## CLI連携・結果判定・エラー表示

- 起動は `analyze <archive> --target <target> [--fast] --jsonl` と[削除実行](#delete-run)の形だけを使う。セッション内のCLIは常に最大1プロセスで、前のプロセスの終了を確認できない間は次を開始しない。
- 出力形式・レコード・フィールド・コード・完了境界・版は[機械可読出力](machine-output.md)が正本である。人間向けの表示文言やCLIのエラーメッセージを判定に使わない。状態の分岐に使ってよいフィールドと表示・診断だけのフィールドの区別は[コード](machine-output.md#codes)に従い、エラーコードで再試行や状態遷移を変えない。未知のコードは一般的なエラーとして表示し、未知のフィールドは無視する。

実行結果の判定 (`analyze` / `delete` 共通): 終了状態の第一の根拠はプロセスの終了コードで、`result` は詳細として使う。

- 正常完了: 終了コード0、出力の非互換・異常が無く、`result` を受信し `outcome` が `completed` で、`result.exit_code` が実際の終了コードと一致する。
- エラー終了: それ以外のすべて (終了コード0で `result` が無い、0・1以外の終了コード、`result.exit_code` との食い違いを含む)。

出力の受信:

- 標準出力と標準エラー出力は、プロセスが終了して両方の出力が閉じるまで並行して読み続ける。非互換・異常を検出した後も受信を止めない (止めるとCLIの書き込みが進まず終了を待てない)。結果はプロセスの実終了と両方の出力の終了を確認してから確定する。
- 標準出力はバイト列をLFで区切ってレコードにし、受信の区切りと行の境界が一致することを前提にしない。LFで終わらない最後の断片の扱いは[出力先と符号化](machine-output.md#destinations)による。
- 次を検出したらそのジョブを出力の非互換・異常としてエラー終了にする: 未知の版 (`v`) のレコード、レコードとして読めない行、`run` の `operation`・`mode` が起動時の指定と違う、`run`・`result` の重複や不可能な順序・型などの破損。
- 非互換・異常を検出しても `delete` のプロセスは強制終了せず終了まで待つ。`analyze` は終了させてよい。
- 標準エラー出力の内容は契約外で、詳細の表示と診断にだけ使う。保持量は制限し、省略したことを示す。

エラー表示: 複数のTargetを見渡すときに各Targetの状態 (未解析・解析中・解析済み・解析失敗・キャンセル・`delete` 実行済み・結果不明など) が簡潔に分かり、Targetごとの詳細としてCLIから得たエラー情報 (終了コード、出力の異常、`result.error`) を確認できる。名前やメッセージに含まれる制御文字・不可視文字は表示用に変換し (生のFullNameや入力パスとは別に保持し、表示文字列からentriesを作らない)、エラー・通知は原因と次の行動を示す。

<a id="session"></a>
## 再検索と永続化

- 再検索は現在の検索セッション (Archive検索結果、Target設定、選択状態、解析結果、削除結果) を破棄する。これらが存在する場合は再検索の前に確認し、取り消せば状態を残す。
- 終了時にセッションを保存しない。次回起動時に保持するのは最後に検索したディレクトリ1件だけで、`%LOCALAPPDATA%\unextract\settings.json` に保存する。設定の読み込み失敗・破損は既定値で起動し、保存の失敗は通知する。多重起動では最後の書き込みが優先される。モード・Target・解析結果は保存しない。
- 例外として `delete` の[実行ログ](#log)はファイルとして残るが、セッションの復元には使わない。

<a id="deployment"></a>
## 配布と同梱CLI

- GUIとCLIは同梱して配布する。配布物は win-x64 の自己完結型フォルダーで、`unextract-gui.exe` と `cli\unextract.exe` からなる。作り方は[ルートREADMEの配布ビルド](../../README.md#配布ビルド)。
- CLIはアプリケーションの配置先の `cli\unextract.exe` だけを使い、PATH・作業ディレクトリ・利用者が指定した別のCLIへフォールバックしない。見つからない、または出力が非互換のときもGUIは起動し、解析・削除を開始できない理由を示す。
- テスト専用の偽CLI・UI自動化ライブラリは配布物に含めない。

<a id="quality"></a>
## 利用品質

画面の分割、一覧と詳細の置き場所、展開・折りたたみの有無、別ウィンドウか画面内の表示か、ボタンの配置と形は、本書の機能・状態・情報を満たすように実装で設計し、現在の画面構造を維持すること自体を目的にしない。どの構成でも次を満たす。

- 初めての利用者が説明書なしで基本の流れ (検索ディレクトリの選択 → 必要なら再帰 → Archiveの確認 → Targetの追加 → 解析 → 結果と候補の確認 → 対象の選択 → 一括削除の確認 → 順次の実行 → 完了・失敗・未処理の確認) を最後まで進められる。次に行う操作と、操作できない理由 (実行中のロック、未解析、`delete` 実行済みなど) が分かる。
- 削除対象・除外したTarget・モード・各Targetの状態と結果を取り違えない。Fastの非保証と、削除が元に戻らないことが埋もれない。削除の操作を他の操作と取り違えにくく、既定の操作にしない。
- 多数のArchive・Targetと大量のエントリ (CLIの[エントリ数上限](zip.md#limits)まで) があっても、必要な情報が隠れて見つけられなくなったり操作できなくなったりせず、画面が応答する。全結果をメモリに保持し、無断で切り捨てない。
- 長いパスも全体を確認できる。マウス専用のツールチップだけに頼らない。
- キーボードだけで主要な操作を行え、Tab順が視覚順に沿い、フォーカスが見える。
- ウィンドウの大きさや表示の拡大率が変わっても、文字欠け・重なりで情報や操作が失われない。

<a id="limitations"></a>
## 既知の限界

- 検索のreparse回避は通常の属性確認によるもので、列挙と同時の差し替えまでをハンドル検証で防ぐ保証ではない。検索結果からの削除の安全性は引き続きCLIが判定する。
- 巨大なファイルの比較中の細かな進捗と、`delete` の即時中断は提供しない (CLIの契約に無い)。
- GUIのクラッシュ・OSによる強制終了・電源断の後の、CLIの完走・ログの完全性・entriesの回収は保証しない。
- GUIはZIPの同一性を固定・検証しない。解析後のZIPの変化のうち受信内容に表れないもの (エントリ数が同じで、受信済みの範囲の名前と `index` も一致し、未受信の部分だけ順序が変わった場合) は検出できない。
- 同一の実体を別のパス (junction など) で指す重複Targetは区別しない ([重複](#targets))。
