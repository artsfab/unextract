### 9.2 README 記載案(§16 と整合させる)

README は §16 の項目と文言を正とする。旧PLANの置き換え案(競合窓が「大幅に縮小でき、事後検出もできる」とする文案)と、クラウドについての「同期状態にかかわらず削除対象にならない」という文案は撤回した。

§16 に加えて書いてよい補足(§16 と矛盾しない範囲。採否は人間が決める):

> unextract は、比較に使ったファイルを削除の直前にもう一度比較し、ファイルIDを照合します。ただし、Windows のごみ箱 API はパスで対象を受け取るため、検証から削除までの競合の時間を完全にはなくせません。unextract の実行中は、target ディレクトリを他のプロセスで変更しないでください。削除の後で、意図しない対象の操作や完全削除を検出した場合は、その時点で処理を中止し、エラーとして報告します(これは事前の保証の代わりではありません)。

> クラウド同期フォルダでは、unextract が識別できる範囲でのみ保護されます。環境によっては、ほぼすべてのファイルがスキップされるか、クラウド状態を識別できずに処理を中止します。

> UTF-8 フラグのない ZIP のファイル名は CP437 として解釈します。日本語(CP932)や、Unicode の正規化形式が異なるファイル名(macOS で作成された ZIP など)は、Missing と判定されることがあります。
